## Проверка fast path и приоритетов

В `backend/llm_router.py` добавлен fast path только для сценариев, у которых в `scenarios.json` установлен `fast_path_eligible=true`, при уверенности rules не ниже 0.80 и отсутствии второй темы. Мультиинтентные реплики дополнительно разбиваются на независимые части; если среди найденных сценариев есть `priority=urgent`, он становится основным, остальные сохраняются в `pending_topics`.

Повторный локальный прогон по всем 104 репликам выполнен в offline-режиме (сетевой доступ к OpenAI в окружении прогона отсутствовал; для не-fast-path вызовов использовался немедленный fallback):

| Режим сравнения | Primary accuracy | Среднее время | P95 | Fast path | Fallback |
|---|---:|---:|---:|---:|---:|
| Правила до изменения | 100.0% (104/104) | 0.10 мс | 0.20 мс | — | — |
| Новый fast path + fallback | 100.0% (104/104) | 0.17 мс | 0.27 мс | 20 | 84 |

Падения точности нет, поэтому fast path оставлен. Эти offline-времена не заменяют production-метрику LLM: предыдущий live-прогон давал среднее `llm_ms=1824.9` мс и P95 `2365.6` мс. Ошибок в локальном прогоне после изменения не обнаружено.

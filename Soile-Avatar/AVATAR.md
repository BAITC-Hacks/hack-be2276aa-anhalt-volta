# 2.5D-аватар Sөile

## Выбранный способ

В проекте фактически используется Streamlit, а не FastAPI из старого `AGENT.md`.
Поэтому голова встроена как постоянный custom component с ключом `soile_avatar`.
Векторные слои SVG имеют разную глубину; CSS perspective и параллакс создают
объём при поворотах. Рот интерполируется между девятью формами Rhubarb A–H/X.
Глаза, случайные моргания, дыхание, взгляд и повороты обновляются через
`requestAnimationFrame`. В Python не отправляются события каждого кадра.
Нет WebGL-модели, генерации изображений или нейросети для рендера. Браузер может
использовать обычное GPU-композитирование CSS; серверный GPU не нужен.

## Запуск и проверка по этапам

```powershell
.venv-avatar\Scripts\python.exe -m streamlit run app.py
```

Или обычная установка из README в исправное Python-окружение. Дополнительных
Python/Node-зависимостей для аватара нет. Откройте http://localhost:8501.

1. **Голова без AI.** Она появляется до первого сообщения и продолжает idle.
   В «Аудиофайл и настройки лица» есть поворот, наклон, отключение idle-движений
   и ручной выбор рта. Водите указателем по сцене: глаза и голова следуют за ним.
   «Слушает · демо» / «Думает · демо» показывают состояние на пять секунд.
2. **Готовый WAV/MP3.** В компоненте можно выбрать локальный файл и нажать Play.
   Кнопка «Демо WAV + visemes» проигрывает включённый пример с системным голосом
   Microsoft Irina: «Привет! Я голосовой ассистент. Чем могу помочь?».
   Для него Rhubarb phonetic сгенерировал 27 интервалов; исходники —
   `avatar_frontend/demo.wav` и `demo.json`. API для этого примера не нужен.
   Такой файл не загружается на сервер. Без таймкодов применяется явно обозначенная
   амплитудная анимация. Загрузите JSON mouthCues для артикуляции или используйте
   серверную панель «Точный lip-sync файла» для анализа Rhubarb.
   Пауза, окончание, ошибка и Stop закрывают рот. Перемотка использует
   `HTMLAudioElement.currentTime`, а не время с момента нажатия Play.
3. **TTS.** Введите «Привет, чем могу помочь?» и нажмите «Произнести».
   Используются установленные голоса браузера/ОС. Выбор голоса доступен рядом.
   Нет гарантии наличия русского/казахского голоса. Оценка артикуляции по буквам
   корректируется на событиях границ слов, когда браузер их предоставляет.
   Это приближение, не распознавание фонем. Для точного результата нужен TTS,
   возвращающий аудио и таймкоды, либо последующий Rhubarb-анализ аудио.
4. **LLM.** Существующие ответы Gemini и локального демо передаются в голову.
   «Ответ из чата» читает последний ответ. «Читать ответы» включает автоматическую
   озвучку новых ответов; сначала нажмите «Произнести», если браузер требует жест
   пользователя для разрешения звука. Смена других виджетов не повторяет ответ.
5. **STT.** Существующая запись Streamlit → Gemini STT → ответ → аватар сохранена.
   Это запись с последующей отправкой, не непрерывный streaming STT.
   Состояние `listening` сейчас демонстрируется вручную и при обработке записи;
   начало/конец записи встроенного `st.audio_input` не выдаёт события компоненту.

## Фонетический lip-sync

Официальный инструмент: https://github.com/DanielSWolf/rhubarb-lip-sync

Укажите путь к `rhubarb`/`rhubarb.exe` в `RHUBARB_PATH` в `.env` или добавьте его
в PATH. Локальная копия `.tools/Rhubarb-Lip-Sync-1.14.0-Windows/rhubarb.exe`
обнаруживается автоматически. Бинарники не включены в Git.
Для MP3 нужен FFmpeg (`FFMPEG_PATH`); WAV можно анализировать без FFmpeg.
Используется `rhubarb -r phonetic -f json`, подходящий для неанглийской речи.
Анализ выполняется один раз по кнопке, на CPU, с таймаутом 120 секунд.
Размер файла ограничен 20 МБ, JSON — 5 МБ. Длинные записи лучше разделить.
Качество фонетического распознавания зависит от дикции, языка и шума.

JSON Rhubarb или провайдера:

```json
{"mouthCues": [
  {"start": 0.0, "end": 0.12, "value": "X"},
  {"start": 0.12, "end": 0.23, "value": "A"},
  {"start": 0.23, "end": 0.48, "value": "D"}
]}
```

Время в секундах от начала конкретного аудиофайла. Интервалы должны быть
упорядочены, без пересечений; промежутки означают закрытый рот.

## Состояния и будущий NVIDIA API

`AvatarState` хранит активность (`idle`, `listening`, `thinking`) отдельно от
флага реального воспроизведения. Если звук идёт, отображается `speaking`.
Окончание генерации переводит активность в idle, но не останавливает звук.
Анимационный цикл не зависит от токенов, результатов API и rerun Streamlit.
Очистка диалога отменяет речь и очередь. Уникальный ID ответа предотвращает
повторную озвучку при повторной передаче параметров компонента.

API внутри iframe:

```javascript
avatar.setActivity('thinking');
avatar.enqueueAudio({
  src: 'data:audio/wav;base64,...',
  cues: [{start: 0, end: 0.2, value: 'D'}]
});
avatar.generationEnded(); // звук и очередь продолжаются
avatar.stop();            // явная отмена речи и очереди
```

Каждый элемент — полностью декодируемый аудиофрагмент с локальными таймкодами.
Очередь ограничена 64 фрагментами; провайдер должен соблюдать backpressure.
Это точка подключения, **не готовый NVIDIA streaming backend**. Очередь на
HTMLAudioElement может иметь небольшие зазоры между фрагментами; для бесшовного
PCM-потока нужен AudioWorklet с общим sample clock.

Текущий Gemini router возвращает валидированный JSON целиком. Его сырые токены
не передаются в TTS: иначе аватар читал бы поля JSON. Настоящий streaming-путь
потребует отдельного генератора устного ответа, буфера предложений и серверного
NVIDIA TTS-адаптера. После выбора NVIDIA endpoint/модели ключ хранится только
на сервере; рот принимает нормализованные mouthCues независимо от провайдера.
На текущем этапе NVIDIA API и L40S не используются и не требуются.

## Файлы и тесты

- `avatar.py`: постоянный компонент Streamlit.
- `avatar_frontend/index.html`, `style.css`: лицо и интерфейс лаборатории.
- `avatar_frontend/avatar.js`: анимация, браузерный TTS, аудио, очередь.
- `avatar_frontend/core.js`: состояния, формы рта и выбор viseme по времени.
- `lip_sync.py`: анализ Rhubarb, MP3 → WAV, проверка таймлайна.

```powershell
.venv-avatar\Scripts\python.exe -m pytest -q
node --test avatar_frontend/core.test.js avatar_frontend/playback.test.js
```

Ручная проверка: моргание → крайние повороты → все формы рта → TTS → Stop →
повторный TTS → WAV/JSON → пауза/перемотка → новый ответ чата → переключение
панели супервизора во время речи → очистка диалога. Idle должен продолжаться.
Визуальное качество и реальную озвучку нужно проверить в целевом браузере:
автоматизированный браузер в среде разработки недоступен.
